# Saarthak Maharana — Portfolio

Portfolio for Saarthak Maharana, 3D environment and ArchViz artist (Delhi, India).
Built with React, TypeScript, Vite, Three.js, GSAP ScrollTrigger and Lenis.

## Run

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # type-check + production build into dist/
npm run preview    # serve the production build
```

## Editing content

All content lives in `src/data/`, so you never need to touch layout or animation code:

- `profile.ts`: identity, bio, experience, education, achievements, tools, services, FAQ, socials
- `projects.ts`: every project and practice render: titles, briefs (summary + description), section order
- `media.json`: generated by `npm run import` (file keys, sizes, video lengths). Don't edit by hand
- `images.ts`: the image registry (every render is referenced by key from here)

### Importing from the project library

The Work page is built from the project library folder (default `D:/Website/My projects`, override with `PROJECTS_DIR`):

| Folder | Section | Notes |
|---|---|---|
| `Unreal & Blender Projects/*.mp4` | 3D Environments | Compressed to 1080p H.264 in `public/video/`, plus a 6 s hover preview and a poster frame |
| `Archviz/<Project>/*` | Architectural Visualization | One folder per project. Files named `NN_ Title - Studio - Location - Year[ - hero]`; the `hero` render becomes the cover |
| `Practice renders/*` | Practice Renders | One tile each |

```bash
npm run import            # everything
npm run import -- images  # renders only
npm run import -- video   # videos only (existing compressed files are skipped; delete one to re-encode it)
```

A new ArchViz folder or video also needs an entry in `src/data/projects.ts` (title and brief). Practice renders get their title and brief from `practiceText` there.

### Adding or replacing a hand-picked still

1. Put the source file in `img/` named `work-<key>.jpg`.
2. Run `npm run images`. It writes optimized `<key>.webp`, `<key>-md.webp` and `<key>-sm.webp` to `public/renders/`.
3. Add or update the entry in `src/data/images.ts` with its pixel width and height.
4. Reference it from a project in `projects.ts`, in the `stills` list of an environment.

## Deploying to GitHub Pages

The `.github/workflows/deploy.yml` workflow builds and deploys on every push to `main`.

1. Push this folder to a GitHub repository.
2. In the repo, go to **Settings → Pages → Source** and select **GitHub Actions**.
3. Push to `main`, or run the workflow manually.

The workflow sets the correct base path automatically: `/<repo>/` for project sites, `/` for `<user>.github.io`.
Deep links like `/work/medieval-castle` work on refresh because the build also writes `404.html` as an SPA fallback.

## Folders

- `src/`: application source (`components/`, `pages/`, `data/`, `lib/`, `styles/`)
- `public/renders/`: optimized WebP renders (generated); `archviz/`, `practice/`, `env/` (video posters)
- `public/video/`: compressed films and hover previews (generated)
- `img/`, `img-src/`: original source images (kept untouched)
- `_legacy/`: backup of the previous single-page site (not used by the build)
